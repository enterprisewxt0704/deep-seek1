### 模式入口
新建会话时选择预设 **「跑团模式」**（`trpg`，推荐）或 **「跑团模式（兼容）」**（`trpg-a`，不替换压缩引擎的 A 档）。
两个预设都不带 bash/文件读写等编码工具；`trpg` 还会把宿主压缩引擎替换成跑团专用摘要模板。

### 面板入口

## 7. v1.2 变更明细（修正串团 + 存档管理 + 面板选团）

**根因**：`.trpg\state.json` 是工作区共享的单份全局检查点。任何新会话在投影为空时都会回读它，于是新团挂上了上一个团的状态，并继续写回同一文件——这就是「界面不同团串了」。

**修复**：
- 每团独立检查点 `.trpg\campaigns\<campaignId>.json`；`campaign.id` 形如 `灰钟港-greybell-harbor-a1b2`。
- 每会话映射 `.trpg\sessions\<sessionId>.json`；新会话只认「自己的投影 → 自己的映射」，不再回读全局文件。
- 旧 `.trpg\state.json` 首次使用新代码时迁移为独立团并改名为 `legacy-state-<时间戳>.json`，**不**自动挂给任何会话。
- 存档按团隔离：文件名带 `campaignId`，`latest.json` 与 `latest__<campaignId>.json` 并存；`trpg_save op=delete` 可按文件或整团删除。
- 新增 `trpg_campaigns`（list/open/new）：可随时列出所有团、切到旧团、另起新团。
- 面板：顶部「看哪个团」下拉 + 存档管理页签（团列表、存档列表、一键填入指令）。

**验证证据**（`.trpg\tooltest.mjs`，2026-11-12 21:20 通过；`.trpg\libtest.mjs`，2026-11-12 21:32 通过）：
- 11 个工具全部注册；两会话同 cwd 隔离（s2 看不到 s1 的世界/角色/骰点）；两个团 id 不同。
- `trpg_campaigns open` 按名/按 id 均可切团，切团后角色卡随团变化；`trpg_world op=new` 清零角色与骰点并换新 id。
- 存档文件名带团 id、列表显示所属团、`campaignId` 读档、整团删除均通过。
- 团文件不写 `library`（避免自我膨胀）；旧全局检查点迁移成功。
- `buildLibrarySync` 同步扫描通过：两个团（含角色名）+ 1 条存档 + activeCampaignId 正确，会话投影 `init` 用它播种索引，**面板在第一次工具调用前就能列出全部团**。
- `buildProjectionDefinition().init({cwd})` 离线测试通过（`.trpg\projtest.mjs`）：新会话索引含两个团与 1 条存档，且 **不会自动挂到任何团**（campaignName 为空）；`apply` 只在 `tool/result.meta.trpg` 时折叠状态、其他事件返回同一引用。
- 全部改动 `node --check` 通过。

**生效方式**：关闭 DSH 再重开（宿主 ESM 模块缓存；重装 bundle 只改文件，不热更新已加载代码）。重启后：
1. 新建会话选「跑团模式」，说「列出所有团」→ 应调用 `trpg_campaigns`；
2. 说「另起一个新团」→ 面板角色/骰点清零、顶部下拉出现两个团；
3. 说「切换到团『灰钟港』」→ 面板切回旧团；
4. 面板下拉选另一个团 → 显示其概览，点「填入：切到此团」→ 输入框出现指令。
