# 跑团模式（dsh-trpg-mode）技术文档

> 版本 1.3.0 · 适用于 DSH Web（desktop profile）· 对应仓库 `enterprisewxt0704/dsh-trpg-mode`
>
> 本文面向维护者：说明插件的分层架构、状态模型、工具契约、数据落盘格式、工具收敛、压缩后端、客户端面板与部署/回滚方式。使用方式的说明见 `docs/guide/跑团模式-使用说明.md`。

---

## 1. 设计目标与边界

| 目标 | 实现方式 |
| --- | --- |
| 新增一个「模式」而不是改宿主 | 通过 bundle 安装：profile 根挂一个全局行 + 声明两个 agent preset |
| 面板显示角色/骰点/团史 | 会话投影（session projection）`trpg`，客户端 `useProjection('trpg')` |
| 存档与读档 | 宿主文件系统写 `.trpg/`，工具 `trpg_save` / `trpg_load` |
| 每团互不串线 | 状态按 `campaignId` 分文件；会话→团映射；旧数据一次性迁移 |
| 与已有插件无冲突 | 不占用已有 slot id / service key / 工具名，全部用 `trpg_` 与 `@local/` 前缀 |
| 不污染普通会话 | 工具注册在**预设会话上下文**内；全局守卫再兜底 |
| 上下文压缩不丢前情 | B 档：子类化宿主 `BasicCompactionEngine`，只覆写 `summarize()` |

**不做的事**：不接管模型路由、不改宿主代码、不写 profile 的 `cordis.patch.yml`（bundle patch 由 loader 读取）。

## 2. 分层架构

```
profile 根（全局，每个会话都有）
  @local/dsh-trpg-mode  ← index.js
    ├─ 注册会话投影 trpg（唯一状态源）
    └─ 导出 buildProjectionDefinition / buildSessionTools（供预设内子路径复用同一模块实例）

agent preset「trpg」/「trpg-a」（只在选中该预设的会话内挂载）
  persona（GM 协议）+ time-context
  compaction 组（isolate: compaction, toolResultPruner）
    ├─ command-compact              ← /compact
    ├─ trpg-compaction 或 compaction-basic  ← 压缩后端（B / A 档）
    ├─ trpg-session                 ← session.js：注册 12 个 trpg_*、/trpg-compact、/trpg-recap、工具收敛
    └─ tool-result-pruner
  tool-ask-user

客户端（web）
  client.js ← __ModuleLoader__ 工厂
    ├─ sidebar.right.pane.tab  → 跑团面板（6 个页签）
    └─ conversation.session.header.utilities → 「跑团」按钮（按预设门控）
```

关键点：**工具的可见性是「会话作用域」的**。`index.js` 在 profile 层不注册任何工具，所以普通会话的工具表与安装前完全一致；只有选中 `trpg`/`trpg-a` 预设的会话才会尝试 `buildSessionTools(ctx)` 并注册 12 个工具。

## 4. 状态模型（`lib/state.js`）

### 4.1 常量

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `PROJECTION_KEY` | `trpg` | 投影 key，同时是 `tool/result.meta` 的键 |
| `STATE_VERSION` | `4` | 投影 stateVersion；v3 引入团隔离，v4 引入开局流程 |
| `SAVE_FORMAT` | `dsh-trpg-save` | 存档文件 `format` 字段 |
| `SAVE_VERSION` | `3` | 存档结构版本 |

### 4.2 状态字段

```js
{
  campaign: { id, name, system, startedAt },
  world: { name, genre, summary, tone, rules[], factions[], locations[], hooks[], notes,
           society, economy, culture, religion, tech, secrets },   // 后 6 个由 v4 问卷归纳
  pc: { name, race, class, level, attributes{}, skills{}, hp{cur,max}, mp{cur,max}, ac,
        inventory[], conditions[], xp, background, goal, notes },
  scene: { title, location, timeLabel, participants[], goal, notes, updatedAt },
  flags: {},
  rolls: [],            // 最近骰点，最多 100 条
  digests: [],          // 团史摘要，最多 30 条
  diceConfig: { defaultId, profiles[{ id, name, sides, weights|null, explode }] },
  timeConfig: { mode: 'estimate'|'fixed', minutesPerTurn },
  clock: { elapsedMinutes, label },
  compactionLog: [],
  library: { activeCampaignId, campaigns[], saves[] },  // 由 Host 每次提交时重建，不写盘
  setup: { ... },        // 开局流程状态（见 §7）
  lastUpdated
}
```

### 4.3 归一化与版本兼容

`normalizeState(raw)` 用「默认值 + 深合并」保证任意旧存档/事件 meta 都能补全缺字段。关键兼容逻辑：

```js
const hadSetup = isObj(raw) && isObj(raw.setup);
s.setup = normalizeSetup(s.setup);
if (!hadSetup) {
  const established = Boolean(s.campaign.id || s.campaign.name || s.world.name || s.pc.name);
  s.setup.stage = established ? 'ready' : 'none';   // 旧团视为已开局，新会话保持未开始
}
```

`stateForDisk(state)` = `normalizeState(state)` 后 `delete library`：`library` 是跨团索引，只存在于投影 wire 与工具 meta 中，绝不写进单团文件，避免团文件互相引用。

### 4.4 骰子数学（纯函数，可离线测）

- `rollOne(sides, weights, rng)`：权重按比例选面，返回 `{ sides, value, weighted }`；`weights` 为 `null` 时均匀。
- `resolveOutcome(rolls, total, target)`：**d20** 自然 20 → `critical`、自然 1 → `critical-fail`；**d100** ≤5 → `critical`、≥96 → `critical-fail`；其余按 `{ type:'ge'|'le', value }` 比较 → `success` / `fail`。
- `formatClock(minutes)`：基准第 1 天 08:00，`第N天 HH:MM`。
- 其余：`slugify`、`nowStamp`（`YYYYMMDD-HHmmss`）、`newId`、`rollSummaryText`。

## 5. 会话投影（`index.js`）

```js
key: 'trpg', stateVersion: 4,
stateSchema: { parse: v => v },          // 鸭子 schema：宿主只调用 .parse()
wire: { viewSchema: { parse: v => v }, view: state => state },
init(header) {                           // 会话建立时：从磁盘播种团/存档索引
  const base = defaultState();
  if (header?.cwd) base.library = buildLibrarySync(header.cwd, base);
  return base;
},
apply(state, event) {                    // 唯一状态变更入口
  if (event?.type !== 'tool/result') return state;
  const next = event.data?.meta?.[PROJECTION_KEY];
  return next ? normalizeState(next) : state;
}
```

要点：

1. **只有携带完整状态的 `tool/result` 会改变投影**；其它事件返回同一引用（宿主按引用判定是否通知）。
2. `meta` 不是 execute 的返回值，而是工具 `output.presentationMeta(args, value)` 的产物 —— 见 §6.1。
3. `init` 播种只做「索引」（哪些团、多少存档），**不自动挂载任何一个团**，因此新会话不会串团。
4. `wire.view` 直接返回 state；客户端 `useProjection('trpg')` 拿到的就是这个对象。
5. `apply(ctx)` 只做 `sessionProjections.register(definition)`，并在 `ctx.effect` 清理时 `dispose()`；句柄存在模块级变量里，供 `session.js`（同一模块实例）通过 `getProjectionHandle()` 读取。

## 6. 工具层（`lib/tools.js`）

### 6.1 定义范式

```js
makeTool(name, description, parameters, run)
  → defineTool({ name, description,
      parameters: toParameterSpec(parameters),      // 转成 dsh-tools 的 value-schema DSL
      output: {
        schema: { type:'object', additionalProperties:true,
                  properties: { text: { type:'string', required:true } } },
        render: (_a, value) => [{ type:'text', text: String(value?.text ?? '') }],
        presentationMeta: (_a, value) => ({ trpg: value?.__trpg ?? null }),
      },
      execute: (args, exec) => run(args ?? {}, exec) })
```

三个容易踩的坑（都是实测结论）：

- **`parameters`/`output.schema` 不是标准 JSON Schema**：必填写在属性内 `required: true`（布尔），对象节点必须显式 `additionalProperties`，未识别关键字会直接抛 authorError。`toParameterSpec()` 负责从普通 JSON Schema 转换（`required: []` 内联、`items:{}` → `{type:'json'}`）。
- **`meta` 只能由 `output.presentationMeta` 产生**：execute 返回的是 `value`（本插件约定 `value.text` 给模型看、`value.__trpg` 给投影），宿主 pipeline 只有在 `presentationMeta` 存在时才把结果放进 `tool/result.meta`。
- `defineTool` 从宿主 `app.asar` 动态导入；离线测试时 `process.resourcesPath` 为空，会降级为直通实现（不影响纯逻辑测试）。

### 6.2 提交范式：getState / commit

```js
getState(exec):  投影有「有意义的团状态」→ 用它；
                 否则读本会话的 .trpg/sessions/<sid>.json → 对应团文件；
                 否则 ensureLegacyMigrated(cwd) 后返回 defaultState()
commit(exec, next, extra):
  1) 归一化 + 补 campaign.id（首次提交才真正建团）
  2) writeCheckpoint → .trpg/campaigns/<id>.json
  3) writeSessionBinding → .trpg/sessions/<sid>.json
  4) buildLibrary → 索引快照
  5) textResult(text, value, { trpg: { ...state, library } })  // 进入投影
```

**不读全局 `.trpg/state.json`**：这是 v1.2 修掉「不同团串线」的核心改动。

### 6.3 12 个工具

| 工具 | op | 关键行为 |
| --- | --- | --- |
| `trpg_world` | get / create / update / new | `new` 另起新团（`freshCampaign`），与旧团完全隔离 |
| `trpg_sheet` | get / create / update / delta | delta 用于 HP/MP/物品等增量修改 |
| `trpg_scene` | get / set | 写场景（地点、在场者、目标、游戏内时间） |
| `trpg_roll` | — | d20/d100/多骰；`target:{type:'ge'|'le',value}`；优势/劣势；结果写入 `rolls` |
| `trpg_dice` | list / set_weights / add / remove / set_default / reset | 自定义骰子概率（权重数组）与默认骰 |
| `trpg_time` | get / advance / set / config | 时间推进；`estimate`（按叙事估计）或 `fixed`（每分钟回合） |
| `trpg_digest` | add / list | 团史摘要（最近 30 条） |
| `trpg_recall` | — | 一次性取回团名/世界/角色/场景/时间/最近骰点/未完成开局提示 |
| `trpg_save` | save / list / delete | 存档；delete 支持 file / name / slot / campaignId |
| `trpg_load` | load / list | 默认读**当前团**最近存档；`campaignId` 读指定团 |
| `trpg_campaigns` | list / open / new | 团列表（当前团标记、存档数）、切换团、新建团 |
| `trpg_setup` | status / questions / record / world / pc_* / place_* / restart / skip | 开局流程状态机（见 §7） |

`trpg_setup` 的完整 op：`status · questions · record · world · pc_method · pc_pointbuy · pc_roll · pc_cards_set · pc_pick · pc_finalize · place_method · place_pointbuy · place_roll · place_finalize · restart · skip`。

## 7. 开局流程（`lib/setup.js`）

### 7.1 状态机

```
none ──(开始问卷)──> world_q ──(20 问答完 + op=world)──> world_ready
  └──(skip)──────────────────────────────────────────────> ready
world_ready ──(pc_method)──> pc_build（自建：购点/随机）
                          └> pc_pick（主持人 3 张卡）
pc_build / pc_pick ──(pc_finalize / pc_pick)──> place_method
place_method ──(place_pointbuy / place_roll)──> place_done
place_done ──(place_finalize)──> ready
restart：任意阶段 → world_q
```

### 7.2 问卷

`SETUP_GROUPS`：5 组 × 4 题 = 20 题（g1 世界底色、g2 世界细节、g3 基调边界、g4 规则挑战、g5 开局玩法），每题含 `options[{value,label,hint?}]` 与 `default`。支持「全默认」：`fillDefaults(setup)` 用每题默认值填满；`missingQuestions`/`answeredCount` 用于进度与门禁。

### 7.3 车卡

| 模板 | 属性 | 范围 | 预算/花费 |
| --- | --- | --- | --- |
| `d20`（默认） | 6 属性 | 8–15 | 27 点；8→0, 9→1 … 14→7, 15→9 |
| `2d6` | 5 属性 | -1…+3 | 6 点 |
| `percentile` | 6 属性 | 20–80 | 240 点 |
| `narrative` | — | — | 叙事向：随机产出 3 个特质 |

- 购点：`validatePointBuy` 返回 `{valid, spent, remaining, attrs, errors}`，**不抛错**，便于反复协商。
- 随机：`rollAttributeSet`；d20 用 4d6 去最低按序、2d6 用映射表、d100 直取；骰面写入 `setup.pcRolls`（保留 10 条），不可重掷。
- 人物卡：`validateCards` 要求正好 3 张且字段/属性合规；`pc_pick` 把整张卡写进 `pc`。

### 7.4 开始地点

- 预算 6 点：`region` 必选且 1 项（2 点）；`landmark` / `faction` / `mood` 各最多 2 个、每个 1 点。
- `validatePlacement` 返回 `{valid, selected, cost, remaining, errors}`；`rollPlacement` 随机抽取并记录骰面。
- `describePlacement` 生成 `scene.title/location/notes` 的默认文本；`place_finalize` 写入场景并进入 `ready`。

## 8. 存档与团隔离（`lib/saves.js`）

### 8.1 目录布局

```
<cwd>/.trpg/
├── campaigns/<campaignId>.json          # 每团一份自动检查点（完整状态，无 library）
├── sessions/<sessionId>.json            # 会话 → 团映射
├── saves/
│   ├── <campaignId>__<团名slug>__<slot>__<YYYYMMDD-HHmmss>.json
│   ├── latest.json                      # 全局最近
│   └── latest__<campaignId>.json        # 每团最近
└── legacy-state-<stamp>.json            # 旧版全局 state.json 迁移后的存档（一次性）
```

文件结构：`{ format:'dsh-trpg-save', version:3, auto, campaignId, createdAt, state }`。

### 8.2 关键 API

| 函数 | 语义 |
| --- | --- |
| `makeCampaignId(name)` | 团名 slug + 4 位随机（防重名） |
| `writeCheckpoint(cwd, state)` | 无 `campaign.id` 则跳过；写团文件 |
| `writeSessionBinding` / `readSessionBinding` | 会话→团映射 |
| `readCampaign(cwd, id)` | 读团文件 |
| `buildLibrary(Sync)` | 扫描团文件 + 存档 → `{activeCampaignId, campaigns, saves}`；`attachSaves` 先按 campaignId、再按团名归团 |
| `migrateLegacyState(Sync)` | `.trpg/state.json` → 团文件 + `legacy-state-*.json`；幂等，`buildLibrary*` 开头自动调用 |
| `writeSave` | 写存档 + `latest.json` + `latest__<id>.json` |
| `listSaves` | 归一化旧档，返回 `{file, name, slot, note, createdAt, campaignId, campaign}` |
| `readSave` | 支持 `file` / `slot` / `latest` / `campaignId`；旧档无 campaignId 时按团名接回已有团 |
| `deleteSave` | 支持 `file` / `name` / `slot` / `campaignId`；校验路径必须在 saves 目录内 |
| `freshCampaign(name)` | 新团空状态，`setup.stage='world_q'` |

### 8.3 为什么不会串团

1. 状态提交只写**当前会话绑定**的团文件；
2. 新会话投影 `init` 只播种索引、不挂团；
3. `getState` 不再读全局 `state.json`；
4. `trpg_load` 默认读「当前团」的 `latest__<id>.json`，读不到才回退全局；
5. 切团（`trpg_campaigns op=open`）会整体替换状态并写新绑定。

## 9. 工具收敛（`session.js`）

跑团会话里模型只应看到 `trpg_*` + `ask_user_question`，否则 GM 会拿 `ops_bash`/`ops_read_files` 去翻源码、改插件（真实踩过），并浪费每轮 prompt。

实现是「**两层**」：

```js
// 1) restrict：从工具表里摘掉（减少 schema token）
agent.ctx.tools.restrict({ allow: [...12 个 trpg_*, 'ask_user_question'] });
//    失败时退化为与 view(agent).restrictableNames 的交集重试

// 2) guard：调用层兜底拒绝（restrict 无法摘除 agent 自身那层注册的工具）
ctx.tools.guard(exec => ALLOWED.has(exec.name) ? undefined : '跑团模式会话不开放工具「…」…');
```

触发点：`agent/created`（首回合前）+ `agent/pre-step`（恢复的旧 agent 兜底）；用 `ctx.get('sessions').get(agent.id).header.agentPreset ∈ {trpg, trpg-a}` 门控，普通预设完全不受影响。

宿主硬规则（实测）：`restrict` 必须调用在 **agent 自己的 ctx** 上（preset ctx 调用会抛 `requires a scoped context`），且只作用于继承来的工具；`allow` 名单含未注册名会整体抛错。因此代码里有 `restrictableNames` 交集回退。

## 10. 压缩（`compaction.js`，B 档）

### 10.1 原理

宿主 `BasicCompactionEngine` 的 `summarize(input, agent, signal)` 是官方唯一扩展点。本插件从 **当前 Harness 的 app.asar 动态导入** 基类（与宿主共享同一 ESM 模块实例，Service 身份一致），子类只覆写该方法：

```
target = configured(summarizationProvider/Model) ?? 最近请求路由 ?? agent.options
messages = [...input.messages, { role:'user', content:[{type:'text', text: TRPG_COMPACTION_INSTRUCTION + 面板状态}] }]
stream → BlockAssembler → 错误映射（LlmError / MAX_TOKENS / UNSUPPORTED_CONTENT / 空摘要）
```

`TRPG_COMPACTION_INSTRUCTION` 的摘要小节：团名与系统 / 世界与当前局势 / 玩家角色 / 当前场景 / 已发生的关键事件 / 悬而未决的线索与伏笔 / 重要 NPC 与人际关系 / 最近判定与骰点 / 未完成的任务 / 下一步可能发生的事；规则要求保留具体数字、与面板状态一致、不必重复整张角色卡（压缩后 GM 会调 `trpg_recall`）。

### 10.2 命令

- `/trpg-compact`：`ctx.compaction.compactNow(agent, signal, commandId)`；要求 agent 空闲（工具调用中不能立即压缩）；错误码映射（busy/cancelled/changed/summary/commit/persistence）到中文提示。
- `/trpg-recap`：`currentState()`（投影优先 → 会话绑定的团文件）输出团名/世界/角色/场景/最近 2 条团史。
- 自动压缩由 `BasicCompactionEngine` 自身机制触发（`auto:true`、`maxTokens:2048`）。

### 10.3 A 档

`trpg-a` 预设用宿主 `compaction-basic`，其余完全一致；B 档出问题时用它兜底。

## 11. 客户端面板（`client.js`）

- 通过 `window.__ModuleLoader__.load({ id:'@local/dsh-trpg-mode', factory })` 注册；React 来自模块表（`require('react')`）。
- **右侧栏标签**：`ctx.slots.inject('sidebar.right.pane.tab', …)` 注册 body；用 250ms 轮询 `ctx.get('sidebarRightTabs')` / `ctx.get('sidebarRight')`（最多约 30s），就绪后
  `tabs.register({ id:'@local/dsh-trpg-mode/sheet', kind:'trpg-sheet', keepMounted:true, title:()=>'跑团', guide:[…] })`。
- **头部按钮**：`conversation.session.header.utilities` 注册 `{id:'trpg-sheet-open', order:20}`，用 `useSession(s => s.agentPreset)` 门控，仅跑团预设显示；点击 `sidebarRight.openTab('trpg-sheet')`。
- **数据**：`props.useProjection('trpg')`；6 个页签：开局 / 角色 / 骰子 / 团史 / 世界 / 存档。
- **选团**：顶部「看哪个团」下拉读写 `state.library.campaigns`；选别的团时切到只读概览（`CampaignView`），不改变本会话的团。
- **动作**：宿主面板 API 没有 submit，因此所有操作按钮走 `insertInstruction()`：`inputActions.captureInsertion()` 取 span + `insertText(text, span)` 把指令填进输入框，由玩家回车发送。
- 样式只用主题 token（`--dsw-alias-*` / `--dsw-specific-*`），不写 DOM、不 iframe。

## 13. 安装、升级与回滚

```bash
# 安装/升级（在 DSH 会话里调用 plugin_manager）
plugin_manager action=install_bundle target=<abs path>/plugin/dsh-trpg-mode
# 卸载
plugin_manager action=remove_bundle target=@local/dsh-trpg-mode
```

- bundle patch 由 loader 读取，**不需要改 profile 的 `cordis.patch.yml`**；profile `package.json` 会增加一条 `link:` 依赖与 bundle 名。
- 含客户端半边的插件安装/改动会返回 `application:"restart-required"`（`restartReason` 常见为 `unmanaged-plugin`）；**必须关闭并重开 DSH**，刷新网页不够（宿主 ESM 模块缓存不会重新执行）。
- 回滚：`remove_bundle` 即可；若需完全恢复安装前状态，用备份目录 `dev/backup/profile-2026-11-10/` 覆盖 profile 的 `cordis.patch.yml` 与 `package.json`（注意：会覆盖用户自己改的 `transcriptView` 等设置），并删除 `node_modules/@local/dsh-trpg-mode` 后重启。

## 15. 已知限制

1. **面板按钮只能填入输入框**：宿主 `inputActions` 无 submit，需玩家回车；这是框架限制。
2. **面板实时数据只属于当前会话的团**：下拉查看其它团是只读概览；切换团要在对话里说「切换到团 X」或点「填入：切到此团」。
3. **压缩后端的面板状态注入仍读旧路径**：`compaction.js` 中 `readStateText()` 读 `<cwd>/.trpg/state.json`；v1.2 起该文件已迁移为 `campaigns/<id>.json`，因此当前摘要不会附带面板状态（摘要质量仍在，只是少了这层保险）。修复方向：改为读会话绑定团文件。
4. **宿主 per-agent 工具无法 restrict 摘除**：即使 `restrict` 成功，仍有宿主每 agent 注册的工具在表里；调用会被 `guard` 拒绝。
5. **改动需重启**：客户端与 Host 新代码都要重开 DSH；`applied` 只表示装配成功。
6. **旧数据一次性迁移**：`.trpg/state.json` 迁移后改名为 `legacy-state-*.json`，不再作为运行态读取；迁移失败时团列表可能为空（可手动恢复该文件重试）。

## 16. 排障清单

| 现象 | 检查 |
| --- | --- |
| 面板不显示/按钮无反应 | 是否重开过 DSH；`cordis_inspect_query client Slots.listSubTree root=sidebar.right.pane.tab` 是否含 `@local/dsh-trpg-mode/sheet` |
| 预设列表里没有「跑团模式」 | `Config.listConfigs(name='@deepseek-ai/dsh-agent-preset')` 是否有 `include:preset-trpg`；`plugin_manager list_plugins` 尾部是否有 `include:dsh-trpg-mode`（enabled/active） |
| 团列表为空 | `.trpg/campaigns/` 是否存在；是否有 `legacy-state-*.json` 待迁移 |
| 工具被拒 | 拒绝文案即 guard 输出；确认会话 `header.agentPreset` 是 trpg/trpg-a |
| 压缩报错 | `/trpg-compact` 只在空闲回合可用；错误码映射见 `session.js` 的 `COMPACTION_ERRORS` |
| `/trpg-recap` 无状态 | 投影为空时会读 `.trpg/sessions/<sid>.json`；确认该会话已提交过工具调用 |

## 17. 数据流（一次工具调用）

```
模型 → trpg_roll(call)
  → tools.pipeline 校验参数 → execute()
      → getState(exec)：投影 state / 会话绑定团文件
      → 计算骰点、更新 rolls、clock 等
      → commit()：normalize → writeCheckpoint → writeSessionBinding → buildLibrary
      → 返回 value = { text, __trpg: {...state, library} }
  → output.render(value) → 模型看到的文本
  → output.presentationMeta(value) → meta = { trpg: state }
  → session 事件 tool/result{meta} 落日志
  → 投影 apply() 折叠 meta.trpg → wire 通知 → 面板 re-render
```

这条链路保证「模型看到的事实」「面板显示」「落盘存档」三者同源。
