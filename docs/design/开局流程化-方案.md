# 跑团模式「开局流程化」方案 v2

> 状态：待评审（未实现）。目标版本：v1.3。
> 面向需求：① 先通过一定数量的问题确定世界观；② 玩家选择「自己车卡」或「主持人提供的人物卡」；③ 选择故事开始地点；④ 人物与开始地点都提供「购点法」与「骰子随机」两种方法；⑤ 完成后提交并上传 Git。

---

## 1. 背景与目标

### 1.1 当前版本（v1.2.1）的做法

- 开局是「自由对话」：玩家说世界观要求，主持人直接 `trpg_world op=create`，再 `trpg_sheet op=create` 建角色，然后开始讲故事。
- 没有固定问卷、没有角色生成规则、没有开始地点选择；角色属性完全由模型自由填写，玩家无法按规则购点或随机。
- 面板有 5 个页签：角色 / 骰子 / 团史 / 世界 / 存档。

### 1.2 目标

把开局做成**可预期、可复现、可存档**的固定流程：

1. **问卷定世界**：20 个问题分 5 组询问，答案驱动世界观生成；玩家可全用默认值快速开局。
2. **角色有两种来源**：玩家自己车卡（购点或骰子随机），或从主持人提供的 3 张人物卡中选 1 张。
3. **开始地点有两种方法**：购点（按预算挑地点要素）或骰子随机（掷表生成）。
4. 全流程有阶段门禁与面板进度，可中断、可恢复；旧团不受影响。

---

## 2. 流程总览

```
┌ S0 立项 ──────────────── trpg_setup op=status / 选团
│   继续旧团 → 结束（旧团默认跳过流程）
│   新团 → S1
├ S1 世界问卷 ───────────── 20 问，5 批 × 4 问，ask_user_question
├ S2 世界观生成与确认 ────── trpg_setup op=world（草案 → 玩家确认 → 写入）
├ S3 角色来源 ───────────── 选择：自建 / 主持人卡
│   ├ 自建 → S3a 购点 ───── trpg_setup op=pc_pointbuy（反复调整）→ op=pc_finalize
│   ├ 自建 → S3b 随机 ───── trpg_setup op=pc_roll（工具掷，记录骰面）→ op=pc_finalize
│   └ 主持人卡 → S3c 选卡 ─ trpg_setup op=pc_cards_set → op=pc_pick → op=pc_finalize
├ S4 开始地点 ───────────── 选择：购点 / 随机
│   ├ 购点 ──────────────── trpg_setup op=place_pointbuy → op=place_finalize
│   └ 随机 ──────────────── trpg_setup op=place_roll → op=place_finalize
└ S5 第一幕 ─────────────── trpg_scene set + trpg_time config，主持人开始叙事
```

**阶段值**存放在 `state.setup.stage`：

`none | world_q | world_ready | pc_method | pc_build | pc_pick | place_method | place_done | ready`

- 每个 `trpg_setup` op 先校验当前阶段，非法跳转返回「下一步该做什么」，而不是静默执行。
- `trpg_setup op=status` 在任何时候可查进度与下一步。
- 玩家可随时说「跳过开局」「用默认值」→ `op=skip`，其余阶段标记为 `skipped`，直接进入 `ready`。

## 3. 世界观问卷（20 问）

分 5 组，每组 4 问，一批发给玩家；每题 3–5 个选项 + 自由填写；每题都有默认值，玩家说「默认」即用默认。

| 2 | 地理尺度 | 单座城市 / 一个区域 / 一整块大陆 / 多个世界 | `world.summary`、地点池 |

### 3.1 提问与记录方式

- 用 `ask_user_question`，**每批 4 问**（共 5 批）；若单次界面容纳不下，退化为每批 3 问（7 批）。
- 玩家可自由填写；空白/「默认」按默认值记录。
- 记录结构：`setup.answers = [{ id, question, answer, source: 'option'|'custom'|'default' }]`。
- 问卷涉及世界秘密的答案（如「邪教横行」）进入 `world.secrets`，面板不展示，避免剧透。

## 4. 世界观生成与确认

- 由主持人（模型）依据 20 个答案生成草案：名称、题材、摘要、基调、规则要点、势力、地点候选池、核心冲突、开场钩子、**玩家已知信息** 与 **隐藏秘密**。
- 草案先在对话里给玩家确认（允许改 1–2 处）。
- 确认后调用 `trpg_setup op=world` 写入：
  - `world`: `name/genre/summary/tone/rules/factions/locations/hooks/notes` + 新增 `society/economy/culture/religion/tech/secrets`
  - 同时生成**地点要素候选池**（6–10 条，每条含 id/name/kind/tag）供 S4 购点使用。
- `stage = world_ready`。

## 5. 角色生成

### 5.1 先选来源

`ask_user_question`：① 自己车卡（购点）② 自己车卡（骰子随机）③ 从主持人提供的 3 张人物卡里选。

> 购点/随机是「自建」的两种方法；主持人卡是第三种来源。若玩家先选「主持人卡」但想改属性，可以退回自建。

### 5.2 购点法

模板随第 13/14 题的规则系统选择，内置三套，默认 d20：

| 模板 | 属性 | 规则 |
| --- | --- | --- |
| d20（默认） | 力/敏/体/智/感/魅 | 基础 8，预算 27；花费 8→0, 9→1, 10→2, 11→3, 12→4, 13→5, 14→7, 15→9；单项 8–15；种族加值另计 |
| 2d6 | 力/敏/心/智/魅 | 基础 0，预算 6，单项 -1…+3（花费 1 点/级） |
| 百分比 | 力/敏/体/智/感/魅 | 基础 40，总预算 240 点，单项 20–80 |
| 叙事 | — | 不点数，写 3 条角色描述 + 3 项专长，工具只记录 |

- `op=pc_pointbuy alloc={...}` 可反复调用，返回剩余点数、每项花费、合法性；
- 写完后 `op=pc_finalize` 补姓名/种族/职业/背景/目标，落 `trpg_sheet`，`stage=pc_build`。

### 5.3 骰子随机法

| 模板 | 掷法 | 说明 |
| --- | --- | --- |
| d20 | 4d6 去最低，按 力→魅 顺序 | 范围 3–18；允许 1 次两项互换（记录） |
| 2d6 | 每属性 2d6 映射 -1…+3 | 记录原始骰面 |
| 百分比 | 每属性 d100 | 直接取值 |
| 叙事 | 随机 3 个特质 + 1 个秘密 | 不生成数值 |

- 掷骰由工具执行并写入 `setup.rolls` 与面板骰子页，**不可重掷**（可选配置：整组重掷 1 次，需玩家明确要求）。
- `op=pc_roll template=...` 返回六组骰面与最终属性；随后 `op=pc_finalize`。

### 5.4 主持人提供的人物卡

- `op=pc_cards_set cards=[3 张]`：每张含 name/race/class/level/attributes/skills/hp/mp/ac/inventory/background/goal。
- 工具检查：属性是否符合当前购点模板（不合规给出提示但可强制通过，记为 `homebrew:true`）。
- 玩家 `op=pc_pick cardId` 选一张；也可让主持人重做一张再 set。
- `op=pc_finalize` 落 `trpg_sheet`。

### 5.5 确认与展示

- 角色页显示：属性来源（购点/随机/卡）、剩余点数或骰面、种族职业背景。
- 面板「开局」页显示当前阶段与下一步按钮（填入指令）。

## 6. 开始地点

### 6.1 两种方法

购点法（按预算挑要素）或骰子随机（掷 4 张表）。

### 6.2 购点法

- 候选池来自 S2 生成的地点要素，分 4 类：区域类型 / 地标 / 势力 / 氛围事件。
- 预算 **6 点**：
  - 区域类型必选 1 项，花 2 点（3 选 1）
  - 地标 0–2 个，每个 1 点
  - 势力 0–2 个，每个 1 点
  - 氛围事件 0–2 个，每个 1 点
- `op=place_pointbuy picks=[id...]`：校验预算与必选，返回组合后的地点描述与剩余点数。
- 结果写入 `scene`（title/location/notes/goal），并追加到 `world.locations`。

### 6.3 骰子随机法

- 4 张 d6 表：区域类型（3 项）、地标（6 项）、势力（6 项）、氛围事件（6 项）。
- 工具掷骰并组合，记录原始骰面；玩家可要求整组重掷 1 次（记录）。
- `op=place_roll` → 展示结果 → `op=place_finalize`。

### 6.4 收尾

`op=place_finalize` 后 `stage=ready`；主持人设置 `trpg_time config`（第 20 题的时间跨度），然后用 `trpg_scene set` 写第一幕场景并开始叙事。

## 7. 新工具：`trpg_setup`

第 12 个工具（现有 11 个）。所有 op 都先校验阶段并返回下一步提示。

| op | 参数 | 行为 |
| --- | --- | --- |
| `status` | — | 返回阶段、已答问题数、下一步、可用的下一步操作 |
| `questions` | group? | 返回 20 问的题面、选项、默认值（供模型组织 ask_user_question） |
| `record` | answers[] | 记录一批答案，合并进 `setup.answers` |
| `world` | world{} | 校验并写入世界设定 + 地点候选池，stage=world_ready |
| `pc_method` | method | `pointbuy / roll / cards`，stage=pc_build/pc_pick |
| `pc_pointbuy` | alloc{} | 校验并记录属性分配，返回剩余点数 |
| `pc_roll` | template? | 工具掷属性，落 setup.rolls |
| `pc_cards_set` | cards[] | 主持人写入 3 张备选卡 |
| `pc_pick` | cardId | 选择某张卡 |
| `pc_finalize` | name/race/class/background/goal | 写 `trpg_sheet` 并 stage=pc_done |
| `place_method` | method | `pointbuy / roll` |
| `place_pointbuy` | picks[] | 校验预算并生成地点草案 |
| `place_roll` | — | 掷 4 张表并生成地点草案 |
| `place_finalize` | title?/notes? | 写 `trpg_scene`，stage=ready |
| `restart` | — | 重新走一遍开局流程（保留旧团数据，需二次确认） |
| `skip` | — | 跳过剩余步骤，stage=ready |

返回一律带 `text`（给玩家看的摘要）与完整 `meta.trpg`（投影）。

## 8. 状态模型（stateVersion 4）

```js
setup: {
  stage: 'none',
  startedAt: null,
  answers: [],          // { id, question, answer, source }
  groupsDone: [],       // 已完成的问卷组号
  worldDraft: null,     // 生成中草稿
  pcMethod: null,       // pointbuy | roll | cards
  pcMode: null,         // self | cards
  pointBuy: { template: 'd20', budget: 27, spent: 0, alloc: {} },
  pcRolls: [],          // { id, dice: [], total }
  pcCards: [],          // 主持人提供的卡
  placeMethod: null,    // pointbuy | roll
  placeDraft: null,     // { picks, title, location, notes }
  placeRolls: [],
  skipped: [],          // 被跳过的阶段
}
```

`world` 新增：`society / economy / culture / religion / tech / secrets`。
`pc` 新增：`background / goal`（原 notes 保留）。

**迁移**：`stateVersion 3 → 4`；旧团 `setup = null` → 视为 `stage='ready'`（照旧玩）。玩家说「重新走开局流程」时用 `op=restart`。

## 10. 预设提示词改写（cordis.patch.yml，两个预设）

在现有 GM 指令前插入「开局协议」：

1. 新团必须先 `trpg_setup status`；按阶段执行，禁止跳过。
2. 问卷：每批调用 `ask_user_question` 问 4 题（5 批共 20 题），资料齐全后 `op=record`；玩家说默认则用默认值。
3. 世界观先给草案，玩家确认后再 `op=world`；秘密放 `world.secrets`，不在对话与面板剧透。
4. 角色先问来源；购点要逐步引导并调用工具校验；随机必须用工具掷骰，不得口算；主持人卡要给出 3 张并等玩家选择。
5. 地点先问方式；购点要展示预算与候选，随机由工具掷表。
6. `op=place_finalize` 后设置时间跨度、写第一幕场景，再开始叙事。
7. 保留原有裁定原则、存档/切团、压缩/recall 规则。

两个预设都改，`trpg-a` 与 `trpg` 仅压缩后端不同。

## 11. 兼容、回滚与风险

- **旧团**：不受影响（setup=null 视为 ready）。
- **数据**：只新增字段与文件，不删旧字段；旧存档可读。
- **回滚**：仍按插件卸载/恢复备份；本次不改 profile 与已有插件。
- **风险与对策**：
  - 20 问疲劳 → 全部有默认值，「快速开局」跳过；答题可中断，`status` 恢复。
  - 模型不守流程 → 每个 op 做阶段校验 + 提示下一步；面板显示进度。
  - 用户规则书与内置模板不符 → 模板可配置，world.system 可覆盖；人物卡允许 homebrew。
  - `ask_user_question` 单批 4 问若界面不适 → 退化为 3 问/批。

## 12. 测试计划

- **单元测试**（`tests/unit/setuptest.mjs`）：
  - 阶段机：非法跳转被拒、`status` 下一步正确、`skip` 生效。
  - 购点：三模板边界、预算越界、剩余点数计算。
  - 掷骰：4d6dl 分布（2 万次，均值约 12.2）、不可重掷、原始骰面记录。
  - 地点：预算 6 点、必选区域、超额拒绝、结果合并。
- **集成测试**（`tests/integration/flowtest.mjs`）：
  - 完整走一遍：20 答 → world → 购点角色 → 购点地点；另一遍走随机 + 主持人卡。
  - 断言：state 字段、投影 meta、scene 结果、团隔离不受影响。
- **旧团迁移测试**：v3 团文件读入后 setup=null → ready，可继续玩。
- **真实会话**：重启 DSH 后用探针驱动一次「20 问 + 角色 + 地点」，检查 ask_user_question 实际交互与面板。
- 验收结果补进 `docs/acceptance/验收报告.md` §8。
