## 0. 结论

**可行性：高（约 90%）。** 所有需求都能在新插件内完成，不需要修改任何既有插件或宿主核心：

| 需求 | 实现手段 | 可行性 |
| --- | --- | --- |
| 侧边栏/其他位置显示角色与 roll 记录 | 右侧栏（rightbar）自定义 tab + 会话投影 | ✅ 已实测座位存在 |
| 以插件形式接入且不与已有插件冲突 | 独立 bundle：新增预设行 + 新增插件行 + 唯一 id 命名空间 | ✅ 不改任何现有行 |
| 存档功能 | 插件 Host 端工具读写工作区 JSON + 面板存档页 | ✅ |
| 开局前由你提要求、AI 生成世界观 | 跑团预设的 GM 提示词 + `trpg_world` 工具 + 交互式确认 | ✅ |

v1.1 追加三项的可行性：自定义骰子概率 **高**（纯 Host 端加权采样）；自定义单回合时间跨度 **高**（投影折叠 `turn/end` + 工具推进）；跑团专用上下文压缩 **中高**——分 A（复用宿主压缩 seam，低风险，v1 默认）与 B（自定义摘要后端，高保真，可选）两档，详见 §7.2。

## 1. 技术依据（本轮已在当前宿主实测，非推测）

1. **主面板 `main` 没有会话绑定**：座位说明原文 “The reserved `conversation` key hosts the Conversation; other keys receive no Session binding.”，standardProps 里没有 `sessionId`。→ 不适合显示“本团”的角色卡。
2. **右侧栏是会话作用域的**：`rightbar.session` → `sidebar.right.pane.tab`（keyed，按 `tab.kind` 分发，scope=session），standardProps 含 `sessionId`、`useSession`、`useProjection`、`useChat`、`useTrajectory` 等。→ 这是显示角色卡 / roll 历史的最佳位置，聊天区不受影响。
3. **第三方插件已成功占用右侧栏 tab**：已安装的壁纸引擎（wallpaper）在 `sidebar.right.pane.tab` 注册了 `dsh-plugin-wallpaper-engine/library`（active），走的是公开路径：
   `ctx.get('sidebarRightTabs').register({ id, kind, keepMounted, title, guide })` + `ctx.slots.register({ name:'sidebar.right.pane.tab', key:id }, Component)` + `ctx.get('sidebarRight').openTab(kind)`。两个服务是**可选服务**，用 `ctx.get` 拿、缺失即降级。
4. **工具可以按预设门控**：`tools.register(def, { when })` 的 `when(ctx: ToolActivationContext)` 可读 `ctx.agent.id`，而 `ctx.sessions.get(id).header.agentPreset` 就是当前会话预设。→ 跑团工具只在跑团模式会话里出现，普通编码会话零污染。
5. **会话投影可直达客户端**：`ctx.sessionProjections.register({ key, stateSchema, stateVersion, init, apply, wire:{ viewSchema, view } })`，客户端在会话作用域组件里直接读投影（wire 视图），插件无需自建 RPC。宿主只对 schema 调用 `.parse()`（已核对源码）。
6. **模式 = Agent 预设**：预设是 `@deepseek-ai/dsh-agent-preset` 的声明行，由 bundle patch 插入；新预设与 `standard` 并存，互不影响；新会话的选择器会出现“跑团模式”。
7. **客户端半区格式**（无需构建工具）：`window.__ModuleLoader__.load({ id, factory(require){ return { inject, apply(ctx){} } } })`，React 由浏览器模块表提供，`host.call(method,args)` 提供 client → 本包 host 的 JSON RPC，`ctx.effect/on` 管理生命周期。
8. **配置持久化**用 `ctx.get('configEditor').edit(entry, …)`，不手改 profile patch。

## 2. 需求映射与功能建议

### 2.1 需求直接映射

- **模式入口**：新建会话时在预设选择器里选「跑团模式」。
- **面板内容**：右侧栏「跑团」tab，4 个页签：角色卡 / 掷骰 / 世界 / 存档。
- **重要信息**：角色属性、HP/SAN/MP、物品、状态、羁绊；最近 100 条 roll 明细（表达式、骰面、总计、原因、DC 与成败）；已确认的世界圣经；当前场景与章节。
- **存档**：工具 `trpg_save` / `trpg_load`，面板存档页可视化列表；文件落在工作区，可自行备份。
- **世界观开团**：AI 先问 3–5 个关键问题（题材、基调、年代、规则系统、禁忌），再产出结构化世界圣经；你确认后才写入并建卡开局。

### 2.2 功能增值建议（建议采纳，均低成本）

1. **玩家层 / GM 层分离**：面板默认只显示玩家可见信息；暗骰、隐藏旗标不进面板（防剧透）。
2. **自动存档**：每次读档/章节结束/手动保存外，每回合结束自动写 `latest.json`；手动槽位独立保存。
3. **读档 recap**：读档时把「世界摘要 + 角色卡 + 最近 5 条 roll + 剧情摘要」注入上下文，防止 AI 失忆。
4. **骰子公平性**：Host 端用 `crypto.randomInt` 生成，逐骰记录原始骰面，面板可复核；支持优势/劣势、COC 成功等级。
5. **规则包**：默认 COC7 风格（d100 + 成功等级），可切 D&D5e（d20+调整值）或自定义表达式；只影响提示词与判定展示，不影响存档结构。
6. **快捷指令**：`/掷骰 1d100 侦查`、`/存档 第三章` 之类（可选，v2）。
7. **团录导出**：把本团对话导出为 Markdown 团录（v2，读 session 事件 + 存档拼装）。
8. **工作区隔离**：一个团一个目录/前缀，避免多个团互相覆盖存档。
9. **不注入编码用 AGENTS.md**：跑团预设不挂 `agent-instructions`，每会话省下约 8–10k tokens 的无关系统提示（很大一块固定成本）。

### 2.3 v1 明确不做

不改已有插件、不引入网络依赖、不做多人联机、不做地图/立绘/语音、不做战斗网格。

## 3. 方案设计

### 3.1 组成：一个 bundle，两半

```
D:\自制跑团\plugin\dsh-trpg-mode\
  package.json          # 包名 @local/dsh-trpg-mode，dsh.bundle.patch + dsh.client
  cordis.patch.yml      # insert 两行：preset-trpg + dsh-trpg-mode
  index.js              # Host：投影、6 个工具、GM 系统提示段、存档读写
  client.js             # Client：右侧栏 tab、header 按钮、composer 状态芯片
  locale/zh.json, locale/en.json, icon.svg
```

安装：`plugin_manager(action="install_bundle", target="D:\\自制跑团\\plugin\\dsh-trpg-mode")`（会弹权限审批，需你确认）。卸载：`remove_bundle`。全程单包，删除即干净。

**唯一 id 命名空间（零冲突）**：

| 项目 | id |
| --- | --- |
| 包名 | `@local/dsh-trpg-mode` |
| 插件行 | `dsh-trpg-mode` |
| 预设 | `trpg`（行 `preset-trpg`，name「跑团模式」，order 20） |
| 投影 key | `trpg` |
| 右侧栏 tab kind | `trpg-sheet` |
| tab body key | `@local/dsh-trpg-mode/sheet` |
| 工具 | `trpg_world` `trpg_sheet` `trpg_scene` `trpg_roll` `trpg_save` `trpg_load` |

### 3.2 模式（预设）内容

`preset-trpg` 的 plugins 只保留跑团必需项（**不继承 standard，也不改动 standard**）：

- `persona`（前缀改为 GM 角色，去掉“coding agent”措辞）
- `time-context`
- `tool-ask-user`（世界观提问用按钮式问答，省 token）
- 压缩组：`compaction-basic` + `command-compact` + `tool-result-pruner`（长团必需）
- `dsh-trpg-mode`（本插件行：注册 GM 提示段 + 6 个工具 + 投影）

不挂：bash / pwsh / fs / 搜索 / 子代理 / 插件管理 / AGENTS.md 注入等，固定开销从 standard 的 ~10k+ 降到 ~3k。

### 3.3 UI 布局

1. **右侧栏 tab「跑团」**（主承载）：会话作用域，聊天区不动。
   - 页签：角色 / 骰子 / 世界 / 存档
   - 顶部：团名 · 章节 · 场景；HP/SAN/MP 条；状态标签
   - 骰子页：时间、表达式、骰面明细、总计、原因、DC→成败；最多 100 条
   - 世界页：已确认的世界圣经（只读，结构化折叠）
   - 存档页：存档列表（名称/时间/章节/摘要），按钮：保存当前 / 刷新列表
2. **会话 header 按钮**（🎲）：`sidebarRight.openTab('trpg-sheet')`，让用户随时唤出/切换。
3. **composer 状态芯片**（可选）：输入框上方一行 `HP 12/14 · SAN 55 · 场景：图书馆`，不占聊天空间。
4. 非跑团会话打开该 tab 时显示空态：「本会话未开启跑团模式」+ 说明如何新建。
5. 窄屏：右侧栏本身支持全屏呈现，无需额外适配。

### 3.4 数据模型（投影 `trpg`，stateVersion 1）

```ts
type TrpgState = {
  v: 1
  campaign: null | { title, genre, tone, era, ruleset, chapter, startedAt }
  world: null | { name, summary, factions[], locations[], npcs[], hooks[], rules[], pcOptions[] }
  pc: null | {
    name, concept, attrs: Record<string, number>,
    skills: Record<string, number>,
    hp: {cur,max}, san: {cur,max}, mp: {cur,max},
    luck, inventory: [{name,qty,note}], statuses: [{name,note}], bonds: [{name,relation,note}]
  }
  scene: { location, time, summary }
  flags: Record<string, string|number|boolean>   // GM 秘密旗标，不进面板
  rolls: [{ seq, ts, expr, faces[], total, reason, dc?, outcome? }]  // 上限 100
  events: [{ seq, ts, summary }]                                     // 上限 30
}
```

- Host 端 `apply` 只折叠**本插件工具的结果**（读 `tool/result` 事件 meta 里的 `trpg` 字段），不订阅、不重扫。
- `wire.view` 输出去掉 `flags` 等隐藏字段并附计数；引用不变则不发布，避免无谓刷新。
- 冷读/重开页面/分叉会话：事件日志重放即可重建，符合“session log 是唯一真相”。
- Client 读法（P1 二选一，先确认精确签名）：组件 props 的 `useProjection('trpg')` 优先；备选 `ctx.sessions.binding(sessionId).session.projections.faceOf('trpg')`。

### 3.5 工具清单（Host，带 `when`：仅 `agentPreset === 'trpg'`）

| 工具 | 作用 | 关键行为 |
| --- | --- | --- |
| `trpg_world` | 写入已确认的世界圣经 | 返回摘要；面板“世界”页随即出现 |
| `trpg_sheet` | 建卡 / 更新角色卡（合并语义） | 返回新卡摘要；HP/SAN 变化即时上面板 |
| `trpg_scene` | 更新场景 / 时间 / 隐藏旗标 | 面板顶部场景行更新 |
| `trpg_roll` | 掷骰 | `crypto.randomInt`；支持 `NdS±M`、优势/劣势、DC 与 COC 成功等级；记录进投影 |
| `trpg_save` | 保存存档 | 写 `<cwd>/.trpg/saves/…json`；无 name 时用 `latest` |
| `trpg_load` | 读取存档 | 无 name 时列存档；有 name 时把整份状态写回投影，并返回 recap 文本 |

工具结果通过 `meta: { trpg: {...} }` 落到 `tool/result` 事件，投影据此折叠；模型上下文里只看到简短确认与必要数据。

v1.1 追加 4 个工具（`trpg_dice`、`trpg_time`、`trpg_digest`、`trpg_compact`），完整清单与说明见 §7.4；工具 schema 固定开销约 2.5–3k tokens/请求（可被前缀缓存覆盖，实际计费远低）。

### 3.6 存档设计

- 目录：`<会话工作区>/.trpg/saves/`（默认 `D:\自制跑团\.trpg\saves\`），每团可用子目录隔离。
- 文件名：`<团名slug>__<槽位>__<YYYYMMDD-HHmm>.json`；另有 `latest.json` 自动覆盖。
- 内容（人类可读 JSON，版本化）：

```json
{ "format": "dsh-trpg-save", "version": 1, "savedAt": "…", "sessionId": "…",
  "campaign": {}, "world": {}, "pc": {}, "scene": {}, "flags": {},
  "rolls": [], "events": [],
  "playlog": [{ "seq": 1, "role": "gm|player", "text": "…" }] }
```

- 读档：工具返回 recap（约 600–1000 tokens），并整体覆盖投影；之后 AI 按 recap 继续。
- 存档页「保存当前」由面板经 `host.call('save')` 触发（Host 读当前投影状态落盘）；「读档」先填一句指令到输入框（或 v1.5 由面板直接发起）。
- 备份/迁移：整个 `.trpg/saves` 目录可直接复制；跨工作区读档用绝对路径参数（v2）。

### 3.7 开局 / 世界生成流程

1. 你新建会话选「跑团模式」，第一句给世界观要求（题材、风格、规则系统、禁忌、期望长度）。
2. AI 用 `ask_user_question` 一次问 3–5 个关键问题（不给选项也可用纯文本）。
3. AI 产出世界圣经：时代/地点/主要势力/关键 NPC/主线钩子/开局场景/角色创建选项/房规；聊天里给摘要，同时调 `trpg_world` 存结构化版。
4. 你确认 → AI 提供 3 个预设角色或问答建卡 → 调 `trpg_sheet` 写入 → `trpg_scene` 定开场 → 开始。
5. 每次「新团 / 新章节」重复 1–4；读档则跳过。

### 3.8 防剧透与公平性

- 暗骰（`hidden: true`）只返回 GM 结果，不写进玩家可见 rolls。
- `flags` 不进 `wire.view`，面板不可见。
- 骰面明细与总计都由 Host 计算并记录，AI 只能引用、不能改写；面板可复核。
- 存档里保留完整骰史，读档后一致。

### 3.9 Token 控制

- 预设裁剪（无 AGENTS.md、无编码工具）。
- 世界圣经结构化存投影/存档，提示词只带摘要，不重复整份设定。
- roll 历史面板显示 100 条、注入上下文只取最近 5 条。
- 长团用压缩插件 + 章节存档 + 新会话续团。

## 4. 实施计划与 token 估算

| 阶段 | 内容 | 验收 | 预估 token |
| --- | --- | --- | --- |
| P1 骨架 | bundle 包、两行 patch、空右侧栏 tab、预设行；安装并确认 roster 激活 | 新会话出现「跑团模式」；右侧栏出现「跑团」且能打开 | 6–10 万 |
| P2 Host | 投影定义 + 6 工具 + GM 提示段 + 存档读写 | 对话中建卡/掷骰/存读档成功，重开页面状态还在 | 10–14 万 |
| P3 Client | 4 页签面板 + header 按钮 + 空态 + 样式 | 面板数据随对话实时更新，暗色主题正常 | 12–18 万 |
| P4 联调 | 实跑一段团、分叉/重启/读档回归、修 bug | 全场景通过，普通编码会话零影响 | 8–15 万 |

**合计约 36–57 万 tokens**（含调试与 1–2 轮返工）；顺利路径约 25–30 万。工期约 2–4 小时（含你验收）。

**v1.1 追加功能后的总额**（三项并入 P2/P3，不新增阶段）：标准 A 档 **约 45–73 万 tokens**；含压缩 B 档另加 P5 预验证与实现 **约 60–93 万**。分项见 §7.5。
本轮调研已消耗约 20 万 tokens，不计入上表。

**运行期（你实际玩团时）估算**：

- 固定开销/请求：GM 提示段 ~1.2k + 工具 schema ~1.5k + persona/时间 ~0.2k ≈ **3k/请求**（有缓存，实际计费更低）。
- 世界生成：一次 **4–8k** 输出（每个团一次）。
- 每回合：新增输入 0.3–1k + 输出 0.4–1.2k，掷骰/建卡各 +50–150。
- 一次 30 回合的团 ≈ **6–12 万 tokens**；存档/读档每次 ≤500 tokens。
- 长团建议每 20–30 回合章节存档并开新会话续团（避免上下文膨胀）。

## 5. 冲突与风险

| 风险 | 影响 | 规避 |
| --- | --- | --- |
| `sidebarRightTabs` / `sidebarRight` 是可选服务 | 老版本宿主无右侧栏 | 能力门 + 降级：composer 芯片 + 聊天内存档；当前宿主已验证存在 |
| `useProjection` 精确签名未在 inspector 展开 | P3 可能要改写法 | P1 先打印组件 props 确认；备选 `binding().projections.faceOf()` |
| 宿主 projection 依赖 zod，插件目录解析不到 | 投影注册失败 | 用鸭子类型 schema（宿主只调 `.parse`）或 vendor 一份 zod；P1 验证 |
| 动态 client 半区无构建期类型检查 | 面板 bug 需手测 | 小步提交 + 页面重载验证；复用 wallpaper 同路径写法 |
| 写盘位置/权限 | 存档失败 | 写会话 cwd 下 `.trpg/`（Host 主进程 node:fs）；失败降级临时目录并明确报错 |
| 投影/存档体积 | 长团变慢 | rolls 上限 100、events 上限 30、wire 精简、章节存档 |
| 安装需放宽权限 | 弹审批 | 你确认后执行；卸载用 `remove_bundle` 完全回滚 |
| 与已有插件 id 冲突 | 极小 | 全部 id 挂在 `trpg` / `@local/dsh-trpg-mode` 命名空间；不 override 任何行 |
| `compaction.compactNow` 要求 agent 空闲 | 工具调用中无法立即压缩 | 工具只置「回合结束后压缩」标记，`agent/status: idle` 时触发；失败退 `/trpg-compact` 命令 |
| 自定义概率被误用/偏置过强 | 体验失衡 | 仅用户发起可在面板改；AI 改动有可见记录与徽章；极端值警告；随存档可查 |
| B 档 vendored 依赖与宿主版本漂移 | 加载失败或运行崩溃 | 先做 P5 预验证，失败回退 A 档；只影响跑团预设 |
| 时间自动推进与叙事冲突 | 时间跳变、节奏错乱 | 默认 `estimate` 由 GM 估算；支持 `manual`；单回合上限告警；`trpg_time set` 可回拨 |
| 投影 `stateVersion` 升级 | 旧存档/旧投影兼容 | 旧档字段按默认补齐；升级时 stateVersion +1 |

## 6. 备选方案（已评估后否决）

- **全局面板（main slot）**：无会话绑定，无法同时服务多个团，且会挤占主聊天区 → 否决。
- **conversation.view 内置视图**：一次只显示一个视图，会盖住聊天 → 否决。
- **纯 skill（提示词 + 工具）无面板**：满足不了“侧边栏显示角色/roll” → 否决。
- **用会话 fork 当存档**：复制整段日志、不能跨会话、不能导出 → 否决，改用 JSON 存档。

## 7. v1.1 追加功能设计（三项）

### 7.0 一览

| 追加功能 | 做法 | 可行性 | 增量 token |
| --- | --- | --- | --- |
| 自定义骰子概率 | 每面/区间相对权重 + 命名方案 + 面板编辑 + 理论概率预览 | 高（Host 端加权采样，一次真实随机） | 3–4 万 |
| 跑团专用压缩 | A：结构化团史 + 注入 + 触发宿主压缩；B：自定义摘要后端 | A 高；B 中（需预验证） | A 5–8 万；B +15–20 万 |

面板页签由 4 个变 5 个：角色 / 骰子 / 团史 / 世界 / 存档。

### 7.1 自定义骰子概率

**能力定义**：不是“改结果”，而是“改分布”——给每个骰面（或面区间）设相对权重，权重为 0 的面永久不会出现；支持命名方案、激活方案、按次覆盖。掷骰仍是一次真实随机（Host 端 `crypto.randomInt` 加权采样），每笔记录完整骰面、方案快照与理论概率，可复核、可存档。

- 数据结构（并入投影 `trpg`）：
  ```
  diceProfiles: [{ id, name, sides, weights: [{from,to,w}], note, updatedAt }]
  diceConfig:  { activeProfileId: string | null }        // null = 公平骰
  diceLog:     [{ seq, at, action, profileName, by: 'user'|'assistant' }]   // 上限 50
  ```
- 语义：`weights` 按区间给相对权重（未覆盖的面按 1；`w:0` = 禁用该面）；`d100` 用区间表达，如 `[{from:1,to:60,w:3},{from:61,to:100,w:1}]`，面板实时显示理论成功率（此例约 64%）。
- 工具：`trpg_dice({action:'list'|'upsert'|'delete'|'activate', profile?})`；`trpg_roll` 增加 `profile?`（本次临时使用某方案）与 `hidden?`。
- 面板：骰子页顶部「骰子概率」区
  - 方案下拉（公平骰 / 自定义方案）+「新建 / 编辑 / 删除」
  - 区间权重编辑器（d100 支持 1–100 区间，滑块 + 输入框），实时条形图显示每面概率
  - 「成功率预览」：填 DC 后显示该分布下的通过率
  - 极端值警告（单面 >90%、通过率 <5% 或 >95%）与「恢复公平骰」一键重置
  - 常驻徽章：当前非公平骰时，面板顶栏与 composer 芯片显示「非公平骰：方案名」
- 公平性约束（防止 AI 偷偷偏置）：AI 只能在你明确要求时改方案；工具写入 `diceLog.by='assistant'`，面板顶部出现黄色提示条；所有方案变更随存档保存，读档可查。
- 验证：开发期用 node 脚本做 10 万次采样统计（分布误差 <1%）；面板显示「理论 / 实测」两列。
- 增量 token：约 **3–4 万**（Host 采样与区间归一 ~150 行，面板编辑器 ~200 行）。

### 7.2 跑团专用上下文压缩

背景：宿主自带 `compaction-basic`（按阈值自动压缩）+ `/compact`，但其摘要指令是编码助手风格，也没有“跑团记忆”结构。本模式做三层，分 A / B 两档：

**A 档（v1 默认，复用宿主能力，低风险）**

1. **`trpg_digest` 结构化团史**：GM 每章 / 每 10–15 回合调用一次，写「章节纪要」：剧情事件、玩家关键选择、NPC 关系变化、未闭合伏笔、时间线、数值变化。落到投影 `digests[]`（留最近 3 章）+ 文件 `.trpg/memory/<团名slug>/chapter-N.md` + 面板「团史」页。
2. **团史注入**：`systemPrompt.context` 每步注入「最近 2 章纪要 + 当前场景 + 未闭合伏笔」（≤800 tokens，可在面板调预算）→ 压缩/重开会话后记忆不丢，相当于把重要信息从聊天历史搬进结构化记忆。
3. **`trpg_compact` 工具**：汇报当前上下文占用（`ctx.tokenMeter`，如「62% / 约 78k」）并置「回合结束后压缩」标记；插件监听 `agent/status === 'idle'`，空闲时调 `ctx.compaction.compactNow(agent)` 真正压缩（复用宿主后端与剪枝），失败则提示改用 `/trpg-compact`。
4. **`/trpg-compact` 命令**（`ctx.commands.register`）：空闲时立即压缩并报告释放的 tokens。
5. **面板「压缩」按钮 + 压缩日志**：显示占用、上次压缩时间、释放 tokens、累计第 N 次（投影 `compactionLog[]`）。
6. **预设调参**：跑团预设里的 `compaction-basic` 用更早阈值（`thresholdRatio: 0.68`、`retainRatio: 0.18`），`summarizationModel` 可选便宜模型；另挂 `command-compact` 与 `tool-result-pruner`。

**B 档（可选增强，高保真，v1.2）**

- 子类化 `@deepseek-ai/dsh-compaction-basic` 的引擎，只覆盖 `summarize()`（官方文档明确其为“唯一的摘要定制钩子”），改用跑团专用摘要指令：章节体结构（发生了什么 / 玩家选择与后果 / NPC 与关系 / 未闭合伏笔 / 时间线 / 数值与物品变化 / 下次开局提示）。
- 只替换**跑团预设**里的 compaction 行，standard 会话继续用原版，零影响。
- 代价：需把 `dsh-compaction` seam、`dsh-compaction-basic` 与 `@deepseek-ai/cordis` 依赖 vendor 进插件目录（约 100–150KB），宿主升级可能失配；必须先做 P5 预验证（加载子类并成功压缩一次），不通过即回退 A 档。
- 增量约 **15–20 万 tokens**、+1–2 天。

**明确限制**：A 档摘要正文仍由宿主内置后端生成（编码助手风格），跑团语义靠 digest 注入与存档兜底；只有 B 档能换掉摘要指令本身。

### 7.3 自定义单回合时间跨度

**定义**：“一回合”= 一次 GM 回复（`turn/end` 事件；可在设置里改为“每条玩家消息”）。每回合推进多少游戏内时间由你配置。

- 配置（`timeConfig`）：
  ```
  mode: 'fixed' | 'estimate' | 'manual'
  spanSeconds: number                 // 默认跨度，如 600 = 10 分钟
  spanRange?: [min, max]              // 可选：每回合在区间内随机
  calendarStart: '1348-03-12 09:00'   // 世界生成时由 GM 与你确定
  advanceOn: 'assistant-turn' | 'user-message'
  maxJumpPerTurn?: number             // 单次推进上限，超出提示确认
  ```
- 推进规则（投影内完成，确定性、可重放）：
  - `fixed`：`turn/end` 时自动 `clock += spanSeconds`（或区间随机值）
  - `estimate`：GM 每回合调 `trpg_time({advance})` 按叙事估算；若该回合未调用，回退 `spanSeconds` 并标记 `estimated`
  - `manual`：只在明确调用 `trpg_time` 时推进；本回合已手动推进则不自动加（`clockAdvancedTurnSeq` 去重）
- 数据：`clock: {epochSeconds, display, dayIndex}` + `timeline: [{seq, at, display, label}]`（最近 20 条，面板可见）
- 工具：`trpg_time({advance?: '10m'|'2h'|'1d'|{seconds}, set?, config?})`
- 面板：顶栏常驻「1348年3月12日 09:20 · 第 3 天」；设置区改模式/跨度/历法；「时间线」列表；存档页显示游戏内时间。
- 存档/读档：`clock`、`timeConfig` 随存档保存与恢复；digest 记录每章起止时间。
- 边界：单回合跨度上限（如 ≤1 年）；历法与纪元在世界生成阶段确定（`trpg_world` 可写 `calendar`）；纯游戏内计数，不涉时区。
- 增量 token：约 **2–3 万**。

### 7.4 数据与接口增量汇总

- 投影 `trpg` 升到 `stateVersion: 2`，新增：`diceProfiles`、`diceConfig`、`diceLog`、`timeConfig`、`clock`、`timeline`、`digests`、`compactionLog`。
- 工具从 6 个增至 10 个：`trpg_world` `trpg_sheet` `trpg_scene` `trpg_roll` `trpg_dice` `trpg_time` `trpg_digest` `trpg_compact` `trpg_save` `trpg_load`；schema 固定开销约 2.5–3k/请求。
